Stripe-Webhooks idempotent machen

Doppelte Events führen zu doppelten Buchungen. Fix über eine Event-ID-Tabelle mit Unique-Key.

Entscheidung

Kontext

Stripe liefert Events mehrfach aus (at-least-once). Unser Handler bucht aktuell bei jedem Eingang.

Entscheidung

Unique-Key auf event_id in event_log; der Handler schreibt die ID in derselben Transaktion wie die Buchung.

Konsequenzen

Migration nötig. Folgeentscheidung zur Aufbewahrungsdauer der IDs.

Kontext

Stripe stellt Events maximal 30 Tage lang erneut zu.

Entscheidung

Event-IDs 90 Tage aufbewahren, danach per Cronjob löschen.

Konsequenzen

Kleiner nächtlicher Job; Tabelle bleibt klein.
Alte Events ohne ID im Backlog.
